# 나만무 팀 공유 룰 (Week 15-16)

> 작성 시점: 주차 시작 시
>
> 이번 주차의 "AI 응용 기술을 활용한 게시판 구현"은 개인 과제다.
> 2026-06-12까지는 각자 AI 기능이 붙지 않은 연습용 기본 게시판 템플릿을 만들며 Next.js(React 기반), FastAPI, PostgreSQL 기반 게시판 제작에 익숙해진다.
> 2026-06-13부터는 새 팀 공통 repository의 main을 기준으로 각자 개인 branch를 분기해 주제별 AI 기능을 붙인다.
> 코치님과의 커피챗 및 팀 논의 결과, 나만무 본 프로젝트 프론트엔드는 Next.js를 사용하기로 했다.
> 이 문서는 개인 과제의 독립성을 유지하고, 서로 기술 선택과 진행 상황을 공유하며 나만무 본 프로젝트를 준비하기 위한 기준이다.

## 4. 개인 구현 관리

| 항목 | 기준 |
|------|------|
| 1단계 Repository | 각자 기본 게시판 템플릿 구현에 사용할 개인 작업 공간 |
| 2단계 Repository | 2026-06-13부터 사용할 새 팀 공통 repository |
| 공통 템플릿 | 새 팀 공통 repository의 main에 기본 게시판 템플릿을 둠 |
| Branch | 각자 main에서 개인 branch를 최초 1회 분기하여 독립 구현 |
| Branch 병합 | 개인 branch는 다시 main으로 합치지 않음 |
| Projects/Issue | 팀 GitHub Projects 또는 이슈에서 개인 담당 태스크로 관리 |
| PR/공유 | 개인 branch 작업은 필요 시 PR 또는 리뷰 흐름으로 공유 |
| Commit | 기능, AI 실험, 문서 변경을 의미 있는 단위로 commit |
| README | 프로젝트 개요, 주요 기능, 아키텍처, RAG/MCP/Agent 구조, 데모, 회고 포함 |

## 6. 보안 / 비용 공유

- `.env`, API key, DB password, OAuth secret, AWS credential은 공유하지 않는다.
- credential이 필요한 경우 값이 아니라 설정 방법과 환경 변수 이름만 공유한다.
- API 사용량과 AWS 비용 이상 징후가 있으면 즉시 공유한다.
- 사용하지 않는 EC2, DB, vector store, storage 리소스는 종료 계획을 세운다.
- 로그, README, 발표자료에 비밀값이 노출되지 않았는지 확인한다.

## 7. 나만무 본 프로젝트 준비 관점

- 1단계 기본 게시판 구현으로 Next.js(React 기반), FastAPI, PostgreSQL 흐름을 각자 익힌다.
- 2단계 AI 확장으로 각자 어떤 기술 스택과 AI 기능이 맞는지 확인한다.
- RAG, MCP, Agent 중 나만무 프로젝트에 실제로 가져갈 가치가 있는 기능을 구분한다.
- 구현 속도뿐 아니라 유지보수, 비용, 보안, 데모 가능성을 함께 평가한다.
- 팀 본 프로젝트에서는 이번 주에 검증한 장점과 한계를 바탕으로 역할과 아키텍처를 정한다.
