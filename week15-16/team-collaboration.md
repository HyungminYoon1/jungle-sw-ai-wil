# 나만무 팀 공유 룰 (Week 15-16)

> 작성 시점: 주차 시작 시
>
> 이번 주차의 "AI 응용 기술을 활용한 게시판 구현"은 개인 과제다.
> 나만무 팀 5명은 하나의 팀 repository를 사용하되, 각자 개인 branch에서 프론트엔드, 백엔드, 데이터베이스, AI 응용 기능을 직접 설계하고 구현한다.
> 이 문서는 공동 repository를 사용하면서도 개인 과제의 독립성을 유지하고, 서로 기술 선택과 진행 상황을 공유하며 나만무 본 프로젝트를 준비하기 위한 기준이다.

## 4. 개인 구현 관리

| 항목 | 기준 |
|------|------|
| Repository | 하나의 팀 repository에서 관리 |
| 공통 템플릿 | 팀장이 배포하는 기본 게시판 템플릿을 기준으로 개인 구현을 시작 |
| Branch | 각자 개인 branch를 생성하여 독립적으로 구현 |
| Projects/Issue | 팀 GitHub Projects 또는 이슈에서 개인 담당 태스크로 관리 |
| PR/공유 | 개인 branch 작업은 필요 시 PR 또는 리뷰 흐름으로 공유 |
| Commit | 기능, AI 실험, 문서 변경을 의미 있는 단위로 commit |
| README | 프로젝트 개요, 주요 기능, 아키텍처, RAG/MCP/Agent 구조, 데모, 회고 포함 |
| 데모 | 기본 게시판 기능과 RAG/MCP/Agent 기능을 각각 시연 가능해야 함 |

## 5. 피드백 기준

| 구분 | 피드백 기준 |
|------|-------------|
| 기본 게시판 | 사용자 흐름이 끊기지 않는지, CRUD/검색/페이징이 명확한지 |
| RAG | 어떤 데이터를 검색하는지, retrieval 결과가 답변에 반영되는지 |
| MCP | 외부 서비스 호출이 실제로 동작하는지, 실패 시 처리가 있는지 |
| Agent | tool 선택 이유, 상태 관리, 종료 조건이 설명 가능한지 |
| README | 아키텍처와 AI 기능 구조가 과장 없이 설명되는지 |
| 발표 | 7분 안에 아키텍처, 데모, 회고가 전달되는지 |

## 6. 보안 / 비용 공유

- `.env`, API key, DB password, OAuth secret, AWS credential은 공유하지 않는다.
- credential이 필요한 경우 값이 아니라 설정 방법과 환경 변수 이름만 공유한다.
- API 사용량과 AWS 비용 이상 징후가 있으면 즉시 공유한다.
- 사용하지 않는 EC2, DB, vector store, storage 리소스는 종료 계획을 세운다.
- 로그, README, 발표자료에 비밀값이 노출되지 않았는지 확인한다.

## 7. 나만무 본 프로젝트 준비 관점

- 이번 개인 과제에서 각자 어떤 기술 스택이 맞는지 확인한다.
- RAG, MCP, Agent 중 나만무 프로젝트에 실제로 가져갈 가치가 있는 기능을 구분한다.
- 구현 속도뿐 아니라 유지보수, 비용, 보안, 데모 가능성을 함께 평가한다.
- 팀 본 프로젝트에서는 이번 주에 검증한 장점과 한계를 바탕으로 역할과 아키텍처를 정한다.
