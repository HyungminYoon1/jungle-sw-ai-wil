# AI 활용 원칙 (Week 15-16)

> 작성 시점: 주차 시작 시
>
> 과제: AI 응용 기술을 활용한 게시판 구현
>
> 이번 과제는 개인 과제다. AI 사용은 허용하되, 프론트엔드, 백엔드, 데이터베이스, RAG, MCP, Agent의 동작 원리를 직접 설명할 수 있어야 한다.

---

## 1. 이번 주 AI 사용 수준

| 수준 | 허용 | 선택 |
|------|------|:----:|
| 일부 사용 | 개념 학습, 공식 문서 이해, 오류 메시지 해석 | □ |
| 학습 보조 | 위 + 설계 검토, 테스트 시나리오 작성, 코드 리뷰, 실패 원인 분석 | □ |
| 코드 생성 | 위 + boilerplate, 일부 구현 코드, 실험 스크립트 작성 보조 | ☑ |

이번 주에는 AI 응용 기능을 구현하는 과제이므로 코드 생성 보조까지 허용한다.
다만 AI가 생성한 코드는 실행, 테스트, 설명 검증을 거친 뒤에만 반영한다.

---

## 2. 허용하는 것

- React, 선택한 백엔드 프레임워크, DB 연결 방식에 대한 개념 정리
- API route, DB schema, 인증/인가 흐름 설계 검토
- RAG 데이터 소스, chunking, embedding, vector store 구성 검토
- MCP server, JSON-RPC 요청/응답, tool schema 설계 검토
- Agent의 function calling, 상태 관리, tool 선택, 종료 조건 설계 검토
- 오류 메시지 분석과 실패 원인 후보 정리
- 테스트 케이스, 데모 시나리오, README 문장 정리
- boilerplate 또는 반복 코드 작성 보조
- 로그 기록, 실험 스크립트, 문서 자동화 보조

---

## 3. 허용하지 않는 것

- 설명할 수 없는 AI 생성 코드를 그대로 제출하기
- API key, DB password, OAuth secret, AWS credential, Personal Access Token, `.env` 값을 AI 대화나 로그에 노출하기
- 외부 서비스 권한을 과도하게 부여한 뒤 검토 없이 사용하기
- RAG/MCP/Agent 기능의 실패 케이스를 확인하지 않고 데모에 포함하기
- AI가 제안한 아키텍처를 보안, 비용, 유지보수 관점 검토 없이 그대로 채택하기
- 사용량이 발생하는 API 호출을 비용 한도 없이 반복 실행하기
- 개인 과제 구현을 다른 사람이나 AI가 대신 완성한 것처럼 제출하기

---

## 4. 필수 검증 기준

AI 도움을 받은 기능은 아래 항목을 확인한 뒤 완료로 본다.

| 구분 | 검증 기준 |
|------|-----------|
| 기본 게시판 기능 | 입력값, API 요청/응답, DB 변경, 화면 반영을 직접 확인 |
| RAG | 검색 대상 데이터, embedding 방식, retrieved context, 최종 답변 근거 확인 |
| MCP | tool 입력 schema, JSON-RPC 요청/응답, 외부 서비스 실패 처리 확인 |
| Agent | tool 선택 이유, 상태 변경, 종료 조건, 무한 루프 방지 확인 |
| 보안 | 비밀값 미노출, `.env` 미커밋, 최소 권한 원칙 확인 |
| 비용 | OpenAI/AWS/vector DB 사용량과 불필요한 리소스 종료 여부 확인 |

---

## 5. 비밀값과 로그 원칙

- `.env` 파일 내용은 출력하지 않는다.
- credential 확인이 필요하면 값이 아니라 존재 여부만 확인한다.
- 로그에는 API key, token, password, connection string을 남기지 않는다.
- README, WIL, 발표자료에는 비밀값 대신 환경 변수 이름만 적는다.
- 배포 또는 클라우드 실습 후 사용하지 않는 리소스는 종료한다.

---

## 6. 이번 주 AI 활용 목표

- AI를 빠른 구현 도구로만 쓰지 않고, RAG/MCP/Agent 구조를 이해하는 보조 도구로 사용한다.
- AI 기능은 "동작한다"보다 "왜 이 입력에서 이런 출력이 나오는지 설명할 수 있다"를 기준으로 검증한다.
- 나만무 본 프로젝트에 들어가기 전에 AI 응용 기능의 설계, 비용, 보안, 실패 처리를 한 번 경험한다.
