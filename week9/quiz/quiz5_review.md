# 문제
5. Semaphore와 Mutex의 특징과 주요 차이점은 무엇인가?

# 답변
Semaphore는 정수 값과 대기열 큐를 가진 동기화 도구로 제한된 수의 자원 접근을 제어합니다. 
특정 자원이나 critical section에 접근할 수 있는 스레드의 갯수를 정해두고, 새로운 스레드가 들어왔을 때 자원이 없으면 대기시킵니다. 사용 가능한 자원의 숫자는 up, down을 통해서 그 값을 조정합니다.

Mutex는 한 번에 하나의 스레드만 critical section에 들어가도록 보장하는 동기화 도구입니다. Mutex는 일반적으로 소유권 개념이 있어서 락을 획득한 스레드가 락을 해제해야 합니다.

*critical section이란 여러 스레드가 동시에 접근하면 문제가 생길 수 있는 공유 자원에 접근하는 코드 구간을 의미합니다.

# 정답
Semaphore와 Mutex는 모두 여러 스레드가 공유 자원에 접근할 때 race condition을 막기 위해 사용하는 동기화 도구이다.

Semaphore는 정수 값과 대기열을 가진 동기화 도구이다. 정수 값은 사용 가능한 자원의 개수를 의미한다. 스레드가 `down` 또는 `wait` 연산을 호출했을 때 값이 양수이면 값을 감소시키고 진행하며, 값이 0이면 대기열에서 block된다. 다른 스레드가 `up` 또는 `signal` 연산을 호출하면 값을 증가시키고, 대기 중인 스레드가 있으면 하나를 깨운다. 따라서 Semaphore는 여러 개의 동일한 자원에 대한 접근 수를 제한하거나, 스레드 간 실행 순서를 맞추는 데 사용할 수 있다.

Mutex는 한 번에 하나의 스레드만 critical section에 들어가도록 보장하는 동기화 도구이다. Mutex는 보통 소유권 개념이 있어서 락을 획득한 스레드가 락을 해제해야 한다. 따라서 하나의 공유 자원을 보호하거나 critical section을 상호 배제할 때 사용한다.

주요 차이점은 Semaphore는 카운터 값을 통해 여러 스레드의 접근을 허용할 수 있지만, Mutex는 일반적으로 한 번에 하나의 스레드만 허용한다는 점이다. 또한 Mutex는 소유권이 있어 lock을 획득한 스레드가 unlock해야 하지만, Semaphore는 반드시 같은 스레드가 `down`과 `up`을 수행해야 하는 것은 아니다.
