# 문제
3. 응용 프로그램을 구현할 때 multiprocess 와 multithread 중 하나를 선택하는 기준은 어떤 것이 있는지 몇 가지 제시하시오.

# 답변
쓰기가 별로 없고, 공유하는 읽기 자원이 많을 경우 멀티 스레드를 사용하는 것이 메모리 사용량을 줄이는데 유리합니다.
쓰기가 많을 경우 멀티 스레드는 공유자원에 동시에 접근하는 과정에서 충돌을 일으킬 가능성이 있습니다. 스레드가 접근하는 데이터를 굳이 공유할 필요가 없다면 멀티 프로세스를 사용하는 것이 유리합니다.
앱 활동 하나에서 발생한 버그가 앱의 다른 활동에 영향을 끼치는 것을 최소화하려면 멀티 프로세스를 사용하는 것이 유리합니다.


# 정답
multiprocess와 multithread 중 하나를 선택할 때는 자원 공유 필요성, 안정성, 메모리 사용량, 통신 비용, 동기화 복잡도 등을 기준으로 판단할 수 있다.

multithread는 같은 프로세스의 주소 공간을 공유하므로 여러 작업이 같은 데이터를 자주 공유해야 할 때 유리하다. 프로세스를 여러 개 만드는 것보다 메모리 사용량이 적고, 스레드 간 전환 비용도 비교적 작다. 하지만 여러 스레드가 같은 메모리에 접근하므로 race condition이 발생할 수 있고, lock이나 semaphore 같은 동기화가 필요하다. 따라서 공유 데이터가 많고 성능이 중요하지만 동기화를 잘 관리할 수 있는 경우 multithread가 적합하다.

multiprocess는 각 프로세스가 독립된 주소 공간을 가지므로 한 프로세스의 오류가 다른 프로세스에 영향을 덜 준다. 따라서 안정성과 격리가 중요한 경우에 유리하다. 또한 작업 간에 공유할 데이터가 적거나, 각 작업이 독립적으로 실행될 수 있다면 multiprocess가 적합하다. 다만 프로세스 간 데이터 공유를 위해 IPC가 필요하고, thread보다 메모리 사용량과 context switching 비용이 클 수 있다.

정리하면, 공유 데이터가 많고 가벼운 병렬 처리가 필요하면 multithread를 선택하고, 작업 간 독립성이 크거나 장애 격리와 안정성이 중요하면 multiprocess를 선택한다.
