# 문제
4. 유저 프로그램에서 스택은 높은 주소에서 낮은 주소로, 힙은 낮은 주소에서 높은 주소로 성장하도록 설계되어 있다. 이렇게 서로 반대 방향으로 설계된 이유를 운영체제 관점에서 설명하시오.

# 답변
잘 모르겠으나그 이유를 추측해보자면 가상주소 공간이 한정되어있는데, 이를 유연하게 사용하기 위함인 것 같습니다. 힙과 스택이 서로 마주보는 방향으로 증가하니까 한쪽이 부족하고 다른 한쪽이 널널할 때 각각의 상한과 하한을 한쪽 방향으로 더 쉽게 변경할 수 있을 것 같습니다.

# 정답
스택과 힙을 서로 반대 방향으로 성장하게 설계한 이유는 한정된 가상 주소 공간을 유연하게 사용하기 위해서입니다.

스택은 함수 호출, 지역 변수, 반환 주소 등을 저장하며 실행 중에 크기가 자주 변합니다. 힙은 malloc 같은 동적 메모리 할당에 사용되며 프로그램 실행 중 필요에 따라 증가합니다.

둘을 같은 방향으로 배치하면 미리 각 영역의 최대 크기를 정해야 해서 공간이 낭비될 수 있습니다. 반대로 힙은 낮은 주소에서 높은 주소로, 스택은 높은 주소에서 낮은 주소로 자라게 하면 두 영역이 서로 마주 보며 커지므로, 한쪽이 많이 필요하고 다른 쪽이 적게 필요할 때 주소 공간을 더 유연하게 사용할 수 있습니다.

운영체제는 두 영역이 충돌하지 않는 한 필요한 만큼 페이지를 할당하다가, 힙과 스택이 서로 만나면 메모리 부족 또는 스택 오버플로우 같은 오류로 처리합니다.
