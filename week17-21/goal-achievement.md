## 1. 문제해결
- **목표:** 사용자 문제 1개, AI가 필요한 이유 1개, 핵심 사용자 흐름 1개, MVP 범위 1개, 기술 리스크 5개 이상을 정의하고, 2-3W 안에 핵심 리스크를 spike 또는 프로토타입으로 검증한다.
- **달성률:** 100%
- **회고:** PRD에서 AI 비용 증가, workflow 진입장벽, 흩어진 사내 지식, 기업용 데이터 거버넌스라는 문제를 명확히 정의했다. 해결 방향도 Agent Builder, 권한 기반 RAG, Audit/Trace, LLM 사용량·비용 관측으로 분리했다. 모델 라우팅 리포트에서는 자동 라우팅이 비용을 줄일 수 있지만 품질이 부족할 수 있다는 점까지 실험으로 확인해, 기술 리스크를 단순 가정이 아니라 수치와 실패 원인으로 다뤘다.

## 2. 설계
- **목표:** 기획, 사용자 흐름, 시스템 아키텍처, AI 처리 흐름, 데이터 흐름, API 계약, DB 또는 저장소 구조, 배포 구조, 보안/비밀값 관리, 비용 관리, 장애 대응, 평가 지표, 발표 데모 흐름 중 10개 이상을 문서화한다.
- **달성률:** 100%
- **회고:** `docs/PRD.md`, `docs/architecture.md`, `docs/data_model.md`, `docs/operational_lifecycle.md`와 feature별 requirements/API/component/test 문서를 역할을 나누어 작성했다. ADR도 72개가 작성되었고 RBAC, audit, RAG, credential, outbound, cost, deployment 같은 정책 결정을 추적할 수 있다. 설계를 기능 설명에 그치지 않고 권한 경계, 실패 처리, 데이터 보존, 테스트 기준까지 연결하였다.

## 3. 구현
- **목표:** 1W에는 기획 발표 가능한 MVP 정의를 완료하고, 2-3W에는 핵심 기능 1개를 입력 -> AI 처리 -> 결과 확인까지 배포 환경에서 동작하게 만들며, 4-5W에는 폴리싱과 발표용 데모 흐름을 완성한다.
- **달성률:** 100%
- **회고:** README 기준 Nodease는 Workflow Builder, Agent Builder, RBAC 기반 RAG, Audit/Trace, LLMOps 기능을 갖춘 플랫폼으로 구현되었다. PRD의 통합 데모 흐름도 권한 요청, Agent Builder 생성, RAG 실행, 관리자 감사, 비용 최적화까지 이어진다. 

## 4. 품질
- **목표:** 핵심 happy path 1개, 주요 예외 상황 5개 이상, AI 응답 지연 UX, 배포 접속, 모바일/반응형, 테스트 또는 정적 분석, 사용자 테스트 5명 이상을 검증하고 결과를 기록한다.
- **달성률:** 82%
- **산정 근거:** 11개 항목 중 happy path, 주요 예외 상황 5개, 배포 접속, 테스트·정적 분석 8개를 완료했다. AI 응답 지연 UX와 모바일/반응형은 부분 완료로 각각 0.5점을 반영해 `(8 + 0.5 + 0.5) / 11 = 81.8%`로 계산했다.
- **회고:** CI 품질 게이트, feature별 test case, PostgreSQL 계약 테스트, lint/typecheck/build 기준을 문서화했다. 모델 라우팅 리포트는 실제 WorkflowEngine과 provider 호출을 사용해 비용, latency, JSON 계약 통과, 품질 점수를 비교했고, 실패 분석도 남겼다. 반면 사용자 5-10명 테스트와 정성 피드백은 진행하지 않았고, AI 응답 지연 UX와 모바일/반응형은 일부 단위 테스트와 timeout/reconnect 계약만 확인했다.

## 5. 유지보수
- **목표:** 팀 GitHub Projects, issue, PR, commit, README, Decision Log 또는 주간 진행상황 자료를 사용해 기능 변경과 의사결정을 추적하고, 5주 동안 주 3회 이상 의미 있는 진행 기록을 남긴다.
- **달성률:** 100%
- **회고:** 프로젝트 기간 동안 거의 매일 커밋을 하였고, ADR 72개와 feature별 문서가 정책·아키텍처·보안·데이터 저장 결정을 추적하면서 유지보수를 하였다. 

## 6. 협업
- **목표:** 데일리 공유, 주간 진행상황 자료, 멘토링 사전 공유, 멘토 피드백 반영, 발표 자료 분담, 코드 리뷰 또는 상호 설명, 장애/리스크 공유 총 7개 협업 항목을 수행한다.
- **달성률:** 71%
- **산정 근거:** 7개 항목 중 데일리 공유, 주간 진행상황 자료, 멘토링, 멘토 피드백 반영, 발표 자료 분담 5개를 수행한 것으로 계산했다.
- **회고:** 팀이 함께 이해해야 하는 PRD, architecture, feature 문서, ADR, CI 품질 게이트를 작성하였다. 특히 보안·권한·비용·장애 대응처럼 팀 합의가 필요한 내용을 ADR로 정리하였다. 다만 코드 리뷰 또는 상호 설명과 장애·리스크 공유 절차는 일관된 팀 프로세스로 정착시키지 못했다.

## 7. 태도
- **목표:** 공지 확인, 기획 리뷰 참석, 중간 발표 참석, 멘토링 준비, 주간 진행상황 제출, WIL 작성, 블로그 URL 포럼 등록, 최종 발표/포스터/영상 준비 총 8개 항목을 완료한다.
- **달성률:** 88%
- **산정 근거:** 8개 항목 중 멘토링 준비를 제외한 7개를 완료해 `7 / 8 = 87.5%`로 계산했다.
- **회고:** 나만무 종료 시점까지 기획, 개발, 발표 데모 흐름, 최종 발표 자료, 포스터와 발표 영상을 준비하고 공식 일정에 참여하였다. 다만 멘토링 자료 사전 공유와 질문·피드백 기록은 일관되게 관리하지 못했다.

## 8. 비즈니스 이해
- **목표:** 서비스가 해결하는 사용자 문제, AI가 필요한 이유, 기존 방식 대비 차이, 핵심 사용자 가치, MVP 범위, 실제 사용자 피드백, 발표 스토리라인을 README/WIL/발표자료에 10문장 이상으로 설명한다.
- **달성률:** 90%
- **회고:** PRD는 Nodease를 "기업 내부 AI workflow/LLMOps 플랫폼"으로 정의하고, 비용을 아는 운영, 자연어로 시작하는 자동화, 권한이 적용된 통합 RAG, 감사 가능한 운영을 핵심 가치로 설명한다. 사용자를 플랫폼 관리자, 빌더, 현업 사용자로 나누고 각 시나리오를 작성했으며, 왜 기업 환경에서 권한, 감사, 비용 관측이 필요한지도 설명했다. 다만 별도의 사용자 테스트와 정성 피드백 수집을 진행하지 못해 실제 사용자 피드백을 제품 개선 근거로 연결하지 못했다.

## 9. AI 활용
- **목표:** AI를 기획, 기술 조사, 설계 검토, 코드 초안, 오류 분석, 테스트 케이스, UX 문구, 발표자료 정리 중 6개 이상에 활용하되, AI가 만든 결과는 직접 이해, 실행, 검증한 뒤 반영한다.
- **달성률:** 67%
- **산정 근거:** 기획, 기술 조사, 설계 검토, 발표자료 정리 4개 영역은 내용을 이해하고 판단한 것으로 계산했다. 코드 초안, 오류 분석과 테스트 케이스는 AI 에이전트의 결정 로그와 결과 요약을 확인했지만 실제 diff, 실행 과정과 테스트 결과를 직접 검증하지 못했으므로 완료로 계산하지 않았다. `4 / 6 = 66.7%`로 계산했다.
- **회고:** AI를 요구사항 정리, 기술 조사, 설계와 ADR 검토, 구현, 오류·CI 실패 분석, 테스트와 엣지케이스 보강, UX 문구, 발표자료와 Q&A 정리에 폭넓게 사용했다. 다만 구현과 테스트 검증을 AI 에이전트에 위임하고 추상화된 결정 로그와 결과 요약을 중심으로 확인했다. 전체 코드 경로와 테스트 실행 결과를 직접 검증하지 않았으므로 AI 결과에 대한 최종 검증 책임을 충분히 수행했다고 보기 어렵다. 앞으로는 AI가 작성한 변경의 핵심 diff, 실패 재현, 최소 관련 테스트와 결과를 직접 확인하고 설명할 수 있을 때만 완료로 반영해야 한다.

## 10. 학습 민첩성
- **목표:** 프로젝트에 필요한 기술 스택, AI 모델/프레임워크, 배포/CI/CD, 데이터 저장소, 보안/비용, 사용자 테스트, 발표/포스터 제작 중 7개 이상을 빠르게 학습하고 실제 산출물에 적용한다.
- **달성률:** 86%
- **산정 근거:** 7개 영역 중 기술 스택, AI 모델·프레임워크, 배포·CI/CD, 데이터 저장소, 보안·비용, 발표·포스터 제작 6개를 산출물에 적용해 `6 / 7 = 85.7%`로 계산했다.
- **회고:** Next.js, FastAPI, Celery, PostgreSQL/pgvector, Redis, Docker Compose, Helm, RBAC, RAG, Audit/Trace, LLM credential, provider usage, outbound proxy, CI quality gate까지 폭넓은 기술을 실제 산출물에 연결했다. 특히 운영 가능한 AI 플랫폼을 위한 보안·비용·권한 경계를 학습하고 ADR로 남긴 점이 강하다. 반면 별도의 사용자 테스트를 수행하지 못해 사용자 관찰과 피드백 기반 개선 경험은 충분히 확보하지 못했다.

## 종합 회고

- **종합 달성률:** 88%
- **가장 큰 성과:** 단순 AI 호출 서비스가 아니라 Agent Builder, 권한 기반 RAG, 감사/추적, 비용 관측과 최적화가 결합된 기업 내부 AI workflow 플랫폼으로 범위를 끌어올렸다.
- **기록된 결과:** 모델 라우팅 실험 결과 보고서에는 비용 절감 가능성과 품질 저하 리스크가 함께 기록되어 있다. 다만 원시 실행 결과와 테스트 과정을 직접 검증하지 않았으므로, 이를 개인이 직접 검증한 성과로 평가하지는 않았다.
