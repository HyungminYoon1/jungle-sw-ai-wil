# Week 17-21 - 핵심 역량 목표 설정

> 작성 시점: Week 17 시작 시
>
> 기준 기간: 2026-06-19 ~ 2026-07-25
>
> 프로젝트: 나만의 무기를 갖기
>
> 주차 매핑: Week 17 = 나만무 1W, Week 18-19 = 나만무 2-3W, Week 20-21 = 나만무 4-5W
>
> 근거 자료: 나만무 공지 원문 9개, `week17-21/team-collaboration.md`, `week17-21/checklist.md`
>
> 이번 기간은 AI가 서비스의 핵심 가치가 되는 팀 프로젝트를 기획, 개발, 배포, 폴리싱, 발표까지 진행하는 것을 기준으로 한다.
> 달성률 산정을 위해 목표는 수치화 가능한 형태로 작성한다.

---

## 1. 문제해결
- **목표:** 사용자 문제 1개, AI가 필요한 이유 1개, 핵심 사용자 흐름 1개, MVP 범위 1개, 기술 리스크 5개 이상을 정의하고, 2-3W 안에 핵심 리스크를 spike 또는 프로토타입으로 검증한다.
- **달성률 산식:** (정의 또는 검증 완료한 문제해결 항목 수 / 9) x 100


## 2. 설계
- **목표:** 기획, 사용자 흐름, 시스템 아키텍처, AI 처리 흐름, 데이터 흐름, API 계약, DB 또는 저장소 구조, 배포 구조, 보안/비밀값 관리, 비용 관리, 장애 대응, 평가 지표, 발표 데모 흐름 중 10개 이상을 문서화한다.
- **달성률 산식:** (문서화한 설계 항목 수 / 10) x 100


## 3. 구현
- **목표:** 1W에는 기획 발표 가능한 MVP 정의를 완료하고, 2-3W에는 핵심 기능 1개를 입력 -> AI 처리 -> 결과 확인까지 배포 환경에서 동작하게 만들며, 4-5W에는 폴리싱과 발표용 데모 흐름을 완성한다.
- **달성률 산식:** (완료한 구현 단계 수 / 8) x 100
  - 1W 기획 아이디어 제출
  - 1W GitHub Projects 준비
  - 1W 기획 초안 제출
  - 1W 기획 발표 자료 제출
  - 2-3W 핵심 AI 기능 MVP 구현
  - 2-3W 배포 환경에서 happy path 검증
  - 4-5W 핵심 흐름 안정화
  - 최종 발표 데모 및 백업 시나리오 준비


## 4. 품질
- **목표:** 핵심 happy path 1개, 주요 예외 상황 5개 이상, AI 응답 지연 UX, 배포 접속, 모바일/반응형, 테스트 또는 정적 분석, 사용자 테스트 5명 이상을 검증하고 결과를 기록한다.
- **달성률 산식:** (검증 완료한 품질 항목 수 / 11) x 100


## 5. 유지보수
- **목표:** 팀 GitHub Projects, issue, PR, commit, README, Decision Log 또는 주간 진행상황 자료를 사용해 기능 변경과 의사결정을 추적하고, 5주 동안 주 3회 이상 의미 있는 진행 기록을 남긴다.
- **달성률 산식:** (의미 있는 진행 기록이 있는 횟수 / 15) x 100 (100% 초과 시 100%로 계산)


## 6. 협업
- **목표:** 데일리 공유, 주간 진행상황 자료, 멘토링 사전 공유, 멘토 피드백 반영, 발표 자료 분담, 코드 리뷰 또는 상호 설명, 장애/리스크 공유 총 7개 협업 항목을 수행한다.
- **달성률 산식:** (완료한 협업 항목 수 / 7) x 100


## 7. 태도
- **목표:** 공지 확인, 기획 리뷰 참석, 중간 발표 참석, 멘토링 준비, 주간 진행상황 제출, WIL 작성, 블로그 URL 포럼 등록, 최종 발표/포스터/영상 준비 총 8개 항목을 완료한다.
- **달성률 산식:** (완료한 태도/참여 항목 수 / 8) x 100


## 8. 비즈니스 이해
- **목표:** 서비스가 해결하는 사용자 문제, AI가 필요한 이유, 기존 방식 대비 차이, 핵심 사용자 가치, MVP 범위, 실제 사용자 피드백, 발표 스토리라인을 README/WIL/발표자료에 10문장 이상으로 설명한다.
- **달성률 산식:** (명시한 비즈니스/사용자 가치 문장 수 / 10) x 100


## 9. AI 활용
- **목표:** AI를 기획, 기술 조사, 설계 검토, 코드 초안, 오류 분석, 테스트 케이스, UX 문구, 발표자료 정리 중 6개 이상에 활용하되, AI가 만든 결과는 직접 이해, 실행, 검증한 뒤 반영한다.
- **달성률 산식:** (검증 기록을 남긴 AI 활용 항목 수 / 6) x 100


## 10. 학습 민첩성
- **목표:** 프로젝트에 필요한 기술 스택, AI 모델/프레임워크, 배포/CI/CD, 데이터 저장소, 보안/비용, 사용자 테스트, 발표/포스터 제작 중 7개 이상을 빠르게 학습하고 실제 산출물에 적용한다.
- **달성률 산식:** (적용 완료한 학습 항목 수 / 7) x 100

---

### 달성률 산식 참고
- 구현과 품질은 실제 사용자 흐름이 동작하는 배포 또는 데모 환경을 기준으로 계산한다.
- AI 기능은 단순 API 호출이 아니라 서비스 핵심 가치와 연결되고, 입력/처리/출력/실패 케이스를 설명할 수 있어야 완료로 계산한다.
- 발표 산출물은 최종 발표, 포스터 세션, 발표 영상, 포트폴리오, 면접 스토리에 재사용 가능해야 완료로 계산한다.
- 비밀값 노출, 비용 폭주, 배포 장애처럼 프로젝트 지속 가능성을 해치는 리스크는 발견 즉시 공유하고 해결 기록을 남긴다.
